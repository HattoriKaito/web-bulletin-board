# 要件定義書（Requirement Definition）

## 1. 目的
本書は「ボートレース予想支援AIアプリ（BoatAI）」における実装機能のレベル分類、および今回の開発スコープにおける「引き算（スコープアウト）」の決定事項を定義する。

## 2. 機能レベル分類

### レベル1：必須機能（MVP／卒制提出に必須）
| 機能名 | 内容 |
|--------|------|
| ユーザー認証 | メール＋パスワードでのサインアップ・ログイン。パスワードはハッシュ化して保存 |
| レース登録・記録機能 | レース基本情報（開催場・レース番号・日付・レース種別［一般戦／SG等］）の登録 |
| 出走表入力機能 | 出走6艇の選手データ・当地成績・全国成績・モーター成績等の手動入力 |
| 直前情報入力機能 | 展示タイム・進入コース・スタート展示・気象条件（風向・風速等）の手動入力 |
| オッズ入力機能 | 3連単オッズ（主要な組み合わせ）の手動入力 |
| AI予想生成機能（3段階） | 出走表確定時点／直前情報公開時点／締切直前の3タイミングでAIが買い目（3連単・5点）を生成 |
| ルール管理機能 | ユーザー独自の分析ルールをテキストで登録・編集・削除でき、AI予想プロンプトに反映 |
| 結果記録機能 | レース結果（着順・払戻金）を記録し、的中判定を自動計算 |
| 収支管理機能 | 実際の買い目とAI提案買い目、双方の収支をそれぞれ計算・記録・比較表示 |

### レベル2：重要機能（余裕があれば実装）
| 機能名 | 内容 |
|--------|------|
| AI対話・深掘り機能 | チャット形式でAIの予想根拠を深掘りできる機能 |
| ルール別成績集計機能 | 登録したルールごとに「適用〇回中、的中×回」等の精度を集計 |
| レース種別ごとの精度集計 | 一般戦／SG等、レース規模別にAI予想・ルールの精度を分けて集計 |
| 教訓自動記録支援 | レース結果確定後、「今回の教訓」を入力しやすいUI（振り返りテンプレート） |

### レベル3：拡張機能（今回スコープ外、将来対応）
| 機能名 | 内容 |
|--------|------|
| 自動スクレイピング機能 | 出走表・直前情報・オッズ・記者予想等を対象サイトから自動取得 |
| 通知機能 | 締切直前や直前情報公開時にプッシュ通知 |
| 複数人比較機能 | 友人同士で同一レースの予想・成績を比較表示 |

## 3. 引き算（スコープアウト）の決定事項
今回の卒制範囲では、以下の機能は明確に実装しない。

1. **自動スクレイピング機能**：対象サイトの利用規約リスクと開発工数を考慮し、今回は手動入力に統一する。将来拡張を見据え、データ入力部分は「入力元＝手動／自動」を切り替え可能な設計思想だけ残す。
2. **不特定多数への公開・SNS的機能**：フォロー、タイムライン、いいね等のソーシャル機能は実装しない。ユーザーは自分＋少数の友人のみで、アカウントごとにデータを完全に分離する。
3. **課金・決済機能**：実際の金銭のやり取りは発生しないため、決済APIとの連携は行わない。収支管理はあくまでシミュレーション上の数値管理にとどめる。

## 4. 非機能要件

| 項目 | 内容 |
|------|------|
| 対応デバイス | PC・スマートフォン両対応（レスポンシブ・PWA対応） |
| セキュリティ | パスワードのハッシュ化（bcrypt等）、ユーザーごとのデータアクセス制御（他ユーザーのデータ閲覧不可） |
| パフォーマンス | AI予想生成のレスポンスは体感10秒以内を目標 |
| 可用性 | 無料ホスティング枠を使うため、バックエンドのコールドスタート（数秒〜十数秒の遅延）は許容する |
| データ保持 | レース記録・ルール・収支データは削除しない限り永続的に保持 |

## 5. ユーザーロール
| ロール | 権限 |
|--------|------|
| 一般ユーザー | 自分のレース記録・ルール・収支の登録／閲覧／編集／削除。他ユーザーのデータは閲覧不可 |

## 6. 今後の検討課題（未確定事項）
- ルールをAIプロンプトにどのように構造化して渡すか（自然文のまま渡すか、カテゴリ分けするか）は詳細設計フェーズで確定する。
- 3連単以外の式別（複勝・2連単等）への対応可否は今回は対象外とし、3連単に一本化する。
