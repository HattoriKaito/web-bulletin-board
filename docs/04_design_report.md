# 設計中間報告書（Design Report）

## 1. 本日の振り返り

本日は、卒業制作（実務レベル課題）として開発する新規Webアプリケーション「ボートレース予想支援AIアプリ（BoatAI）」について、テーマ決定から要件定義・詳細設計までを一問一答形式のブレインストーミングを通じて固めた。

出発点は「ボートレースの勝率を、経験を重ねるほど上げていきたい」という個人的な課題意識だった。そこから対話を重ねる中で、単なる予想記録アプリではなく、「AIに予想させる」「自分の分析ルールをAIに学習・反映させて育てていく」という、より挑戦的でオリジナリティのあるコンセプトへと発展した。特に、出走表・直前情報・オッズという時間経過とともに変化する情報を、3段階のタイミングで区切ってAI予想を更新していくという設計は、実際の予想フロー（骨格→直前情報→最終オッズで確定）を踏まえた、実用性の高いアイデアになったと思う。

また、SGのような大舞台ではなく、開催数の多い地方の一般戦でルールを鍛えていくべきという方針も、試行回数の観点から論理的に導き出せた点は良い議論だった。

## 2. 決定した主要事項

- テーマ：ボートレース予想支援AIアプリ（自分＋少数の友人向け）
- コア機能：レース記録、AI予想（3段階更新）、ルール蓄積・管理、収支管理（AI提案 vs 実際の比較）、AI対話深掘り
- 技術スタック：React＋FastAPI＋Supabase（PostgreSQL）＋Claude API
- 認証：メール＋パスワードによるユーザーごとのアカウント管理
- デプロイ：Vercel／Render／Supabaseの無料枠構成
- モバイル対応：PWA化によりスマートフォンからも利用可能
- スコープアウト：自動スクレイピング、SNS的公開機能、課金・決済機能

## 3. 自己評価

今回のブレストでは、抽象的なアイデア（「勝率を上げたい」）から出発し、具体的な機能要件・技術選定・スコープの線引きまで、段階的に解像度を上げていくプロセスを実践できた。特に「情報源をどう取り込むか」「AI予想をどのタイミングで更新するか」という技術的に難しい部分について、自分の普段の予想フロー（骨格更新→"決定？"の確認プロセス）を言語化し、それをシステム設計に落とし込めた点は評価できると思う。

一方で、AIへのルールの渡し方（プロンプトの構造化方法）や、ルールごとの精度集計の具体的な集計ロジックなど、詳細設計フェーズでさらに詰めるべき技術的な検討課題も残っている。次のステップでは、これらの技術的な詳細をより具体化し、実装計画（マイルストーン）に落とし込んでいく必要がある。

## 4. メンターAIからの激励メッセージ

自分の趣味である「ボートレース予想」を、単なる趣味の域にとどめず、AI・Web開発の技術力を証明する卒業制作にまで昇華させた発想力は素晴らしい。特に、経験則をルールとして蓄積し、AIの精度を継続的に育てていくという設計思想は、実務のプロダクト開発でもよく使われる「フィードバックループを持つシステム」の考え方そのもの。ここまで筋道立てて要件を詰められたのは、大きな強み。

ここからは実装フェーズ。焦らず、レベル1（必須機能）から着実に積み上げていけば、必ず動くものが完成する。困ったときはいつでも相談してほしい。応援してる。
