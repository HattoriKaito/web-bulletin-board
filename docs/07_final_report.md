# 07. 最終総合報告書（Final Report）

## 1. アプリの全体概要

BoatAI（ボートレース予想支援AIアプリ）は、ボートレースの3連単予想の的中率向上を
目的としたAI予想支援Webアプリケーションである。自分自身とごく少数の友人のみが使う
クローズドなツールとして設計しており、不特定多数への公開は想定していない
（`docs/01_proposal.md`参照）。

単なる記録ツールにとどまらず、ユーザー自身の分析ルール（経験則）をテキストで
蓄積し、それをAIの予想プロンプトに反映させることで、レースを重ねるほど予想精度を
育てていくことをコンセプトとしている。出走表確定時点・直前情報公開時点・締切直前
（最終オッズ確定時点）という、実際の予想フローに沿った3段階でAI予想を更新していく
点が本アプリの中核的な設計である。

## 2. 機能一覧

| カテゴリ | 機能 |
|---|---|
| ユーザー認証 | メール＋パスワードによるサインアップ・ログイン（bcryptハッシュ化・JWTセッション） |
| レース記録 | 開催場・レース番号・日付・レース種別（一般戦／G3〜SG）の登録 |
| 出走表入力 | 選手名・当地/全国/モーター勝率・フラグの入力、画像からのAI自動入力 |
| 直前情報入力 | 進入コース・展示タイム・気象条件（天候・風向・風速）の入力、画像からのAI自動入力 |
| 追加情報入力 | ピットレポート・コンピューター予想等の自由形式情報の入力、画像からのAI自動抽出・分類 |
| オッズ入力 | 3連単オッズの手動入力、および画像からの一括AI自動入力（最大120通り） |
| AI予想生成 | 出走表確定時点／直前情報時点／締切直前の3段階で3連単5点を提案。要約根拠・詳細根拠を提示 |
| AI対話・深掘り | 個別の予想結果について、その予想の根拠データを踏まえたチャット形式での深掘り |
| ルール管理 | 分析ルールの登録・編集・有効/無効切り替え、AI予想プロンプトへの反映 |
| ルール別成績集計 | ルールごとの「適用〇回中、的中×回」の集計（AI提案買い目基準） |
| レース種別別精度集計 | 一般戦／SG等、レース種別ごとのAI予想的中率集計 |
| 買い目確定・記録 | 実際の買い目とAI提案買い目（自動コピー）の両方を記録 |
| 結果記録・的中判定 | 着順・払戻金の記録、全角/半角を正規化した上での自動的中判定 |
| 収支管理 | レース単位・全体単位で、実際の買い目とAI提案買い目それぞれの収支を算出・比較表示 |
| モバイル対応（PWA） | manifest／Service Workerによるホーム画面追加・レスポンシブレイアウト |

## 3. 技術構成

フロントエンドはReact + TypeScript + Vite（PWA対応）、バックエンドはPython + FastAPI、
データベースはSupabase（PostgreSQL、Row Level Securityによるユーザー間データ分離）、
AI連携はAnthropic Claude API（予想生成・画像認識・チャット応答のすべてに利用）。
デプロイはVercel（フロント）／Render（バックエンド）／Supabase（DB）のいずれも無料枠。
技術スタックの詳細・環境構築手順は`docs/05_implement_guide.md`を参照。

## 4. 当初の要件定義からの変更点・追加機能

`docs/02_requirement_definition.md`で定義したレベル1（必須機能）は全項目を実装済み。
レベル2（重要機能）は以下の状況である。

| レベル2機能 | 状況 |
|---|---|
| AI対話・深掘り機能 | 実装済み |
| ルール別成績集計機能 | 実装済み |
| レース種別ごとの精度集計 | 実装済み |
| 教訓自動記録支援（振り返りテンプレートUI） | **未実装**（ルール管理画面で自由文としての登録は随時可能だが、レース結果確定後に入力を促す専用の振り返りUIは未着手） |

また、要件定義段階では想定していなかった以下の機能・改善を、実運用しながらの
フィードバックを踏まえて追加している。

- **画像からのAI自動入力**：出走表（事前情報・直前情報）・オッズ・追加情報の
  4箇所すべてで、スクリーンショット画像をアップロードするとClaude Vision APIが
  構造化データを抽出してフォームに仮入力する機能。読み取りに自信が持てなかった
  項目は自動的にハイライト表示し、ユーザーが確認・修正してから保存する設計とした
  （抽出結果を直接DBに保存することはしない）。
- **追加情報機能（ピットレポート・コンピューター予想の取り込み）**：出走表・
  直前情報・オッズという固定フォーマットの情報だけでは拾いきれない、自由記述の
  予想材料を取り込めるようにした。AI予想生成時にはこの内容もプロンプトに含め、
  根拠文中で「ピットレポートによると…」のように明示的に言及されるようにしている。
- **UI/UXの刷新**：navyダークテーマ・艇番カラーバッジ（実際のボートレースの
  コースカラーに準拠）・専用フォントによる一貫したデザインシステムを全画面に適用。
- **細かな入力UX改善**：画像アップロード欄へのクリップボード直接ペースト対応、
  開催場入力のオートコンプリート化（全国24場、自由入力併用）、ログイン・
  サインアップ画面へのブラウザ標準パスワードマネージャー連携（`autocomplete`属性）。
- **サインアップ画面の独立実装**：当初のログイン画面と一体で進める想定だったが、
  新規ユーザー登録の導線を独立した画面として整備した。

## 5. 今後の課題

### 5-1. 未実装のレベル2・レベル3機能

- **教訓自動記録支援**：レース結果確定後に「今回の教訓」を入力しやすい振り返り
  専用UI（テンプレート形式）。現状はルール管理画面から手動で登録する運用で
  代替しているが、結果確定のタイミングで自然に入力を促す導線があると、
  ルールの蓄積がより習慣化しやすいと考えられる。
- **自動スクレイピング機能**（レベル3）：出走表・直前情報・オッズ・記者予想等を
  対象サイトから自動取得する機能。今回は利用規約リスクと工数の観点から
  スコープアウトしており、手動入力（＋画像からのAI自動入力による補助）で
  代替している。
- **通知機能**（レベル3）：締切直前や直前情報公開時のプッシュ通知。
- **複数人比較機能**（レベル3）：友人同士で同一レースの予想・成績を比較表示する機能。
  現状は各ユーザーのデータがRLSで完全に分離される設計のため、実装する場合は
  「特定のレースに限り、特定の他ユーザーに閲覧を許可する」ための新しい
  RLSポリシー設計が別途必要になる。

### 5-2. 運用コスト・制約に関する課題

- **無料枠の制約**：Renderの無料プランはアイドル時にスリープするため、
  久しぶりのアクセス時に初回応答が数十秒遅れる。Supabase／Vercelの無料枠にも
  帯域・実行時間等の上限があり、利用者が増えた場合は有料プランへの移行を
  検討する必要がある。
- **Claude APIの従量課金**：AI予想生成・画像認識・AI対話のすべてがAPI呼び出しの
  たびに課金される。開発中、実際にAPIキーのクレジット残高が不足してリクエストが
  拒否される事象が発生しており、継続利用にはクレジット残高の運用管理が
  必要になる。
- **オッズ自動入力の速度と精度のトレードオフ**：オッズ表画像からの一括抽出は
  現状、精度を優先した実装になっており、処理時間の最適化は行っていない
  （ユーザー側の判断で、今回は速度改善を見送っている）。
- **自動テストの整備**：現状の検証は、実装のたびに実Postgres・実Claude API・
  実ブラウザ（Playwright）に対して手動でスクリプトを実行し、検証後に削除する
  形で行っており、CI等での自動テストパイプラインは整備していない。継続的な
  開発・保守を行う場合、リグレッション防止のための自動テストスイート化が
  今後の課題である。
- **教師データ・ルールの蓄積量**：本アプリのコンセプトである「ルールを蓄積して
  AI予想精度を育てる」という価値は、実運用でレースを重ねてルール・実績データが
  蓄積されて初めて検証できる。現時点ではルール別集計・レース種別別集計の
  仕組み自体は完成しているが、実際に精度が向上していくかどうかは、今後の
  継続利用を通じて確認していく必要がある。
